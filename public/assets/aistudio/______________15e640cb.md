# 果壳碰碰｜网页版本开发交接说明

> 可直接交给其他 AI 开发。本文自包含，不要求接手者阅读前面的讨论。
> 范围：参赛演示用网页版本，包含前后端、数据持久化与 AI 接口。
> 本文没有工期排期，也不规定 UI 风格、配色、布局或视觉设计。
> 项目尚未在本次任务中实施；下文是待实现的需求和验收依据。

## 一、给接手 AI 的任务

请实现“果壳碰碰”的网页演示版本。

果壳碰碰是一个结合天然果实手作娃娃与 AI 角色的参赛项目。用户可以打开娃娃的固定链接与它聊天，也可以上传自己的照片、选择人格、生成专属娃娃形象，给娃娃起名字，并再次通过固定链接找到这个角色。

本次先完成浏览器内的完整业务流程。对话和生图接入真实模型，实体出图使用明确标注的模拟执行器。后续 RDK、NFC 标签、机械臂和打印机通过约定接口接入。

请按照本文交付一个能运行、能保存数据、能重复演示的应用。现有项目优先沿用已有技术栈；空项目可自行选择成熟且熟悉的 Web 技术栈，并在 README 记录选择。常规实现细节由开发 AI 决定，不需要为了框架选择中断任务。

### 项目成功的具体表现

一位用户上传照片，选择人格，给娃娃起名“栗子”，并告诉它自己的称呼是“小林”。系统生成专属形象并创建个人娃娃。用户打开该娃娃的固定链接后，角色能够使用自己的形象与人格回应，知道用户的称呼，并正确提到刚才的选择。关闭并重新打开同一链接后，这些数据仍然存在。

以上信息必须来自用户本轮实际输入与保存的数据。

## 二、已经确定的范围

### 必须实现

1. 匿名会话，同一浏览器可以续接。
2. 根据 dollId 加载娃娃资料和人格。
3. 真实流式对话、聊天记录保存。
4. 少量明确记忆的保存、读取和删除。
5. 上传照片；支持摄像头采集与相册文件。
6. 真实形象生成、异步状态查询、结果保存、有限重生成。
7. 选择成功版本并绑定成个人娃娃。
8. 娃娃固定链接、形象结果链接、二维码编码数据。
9. 生成结果下载。
10. 模拟出图任务、状态查询、防重复提交。
11. Provider 配置检查、运行记录和受保护的演示重置。
12. 启动说明、环境变量示例、接口文档和演示步骤。

### 本版不实现

- 注册登录、短信验证、第三方账号、换设备找回。
- 社交广场、关注、评论、支付、会员和订阅。
- 语音对话、向量数据库、复杂自动记忆系统。
- NFC 读写控制、RDK 本地模型部署。
- 机械臂运动控制、实体打印、抓取材料、机器狗联动。

NFC 在本版对应“打开一个固定链接”的入口能力。出图在本版对应“创建和查询一个模拟任务”的能力。

## 三、核心对象及规则

### 3.1 匿名会话 Session

- 服务端生成随机会话身份，以 HttpOnly Cookie 识别。
- 本演示应用新建会话默认 isDemo=true，供受保护的本轮重置识别。
- 浏览器请求不通过自行填写 ownerId 或 visitorId 获得身份。
- 同一浏览器在 Cookie 有效时可以恢复数据；默认有效期 30 天，可配置。
- 清除 Cookie、使用另一浏览器或另一设备的恢复不在本版范围。
- 原始照片、生成记录、聊天、记忆与出图任务按会话进行访问检查。

### 3.2 人格 Persona

- 人格通过配置维护，包含 id、name、mbti、prompt、openingLine。
- 支持 16 种 MBTI 类型，重点验证 3–4 个不同表达风格的演示角色。
- 人格由用户选择或现有娃娃配置确定。
- 照片用于外形生成，不用于推断用户的真实人格。
- 模型输出的字段不能覆盖用户已经明确选择的人格。

### 3.3 娃娃 Doll

分为两种：

| 类型 | 用途 | 修改规则 |
| --- | --- | --- |
| demo | 预置展示娃娃，任何访客都能开始自己的会话 | 配置只读，用户生成的卡片不能覆盖它 |
| personal | 由成功形象版本创建的个人娃娃 | 本版采用一次绑定，不提供换形象或转赠 |

公开 dollId 只用于获取娃娃公开资料。不同访客与同一娃娃的聊天和记忆分别保存。

### 3.4 形象卡 Card 与版本 CardVersion

Card 是一次创作的容器，CardVersion 是一次具体的生成尝试，同时承担生成任务记录。

固定规则：

- 第一次生成创建 Card 和第一个 CardVersion。
- 每次重生成新增版本，不能覆盖旧版本和旧图。
- 默认初次生成后最多重生成 2 次，即最多 3 次模型生成尝试。
- 失败尝试也计次数；网络重复提交不额外计次。
- 同一个 Card 同时最多有一个 queued 或 running 的生成版本。
- 模板兜底作为独立版本，resultKind=template，不计模型生成次数；同一卡片最多保留一个模板兜底版本。
- Card.activeVersionId 指向当前尝试，用户绑定时必须明确提交选定的成功 versionId。
- 个人 Doll 与出图任务均引用明确的 cardVersionId。
- 已绑定的 Card 冻结，不能继续重生成。需要其他形象时新建 Card。
- 对已绑定 Card 重复绑定，返回原 Doll，不创建重复角色。

### 3.5 聊天 Message 与记忆 Memory

聊天历史和记忆分别存储。

本版记忆只保留：

- 用户称呼；
- 娃娃名称；
- 创建过程中明确选择的人格和配饰；
- 用户明确要求记住的一件或几件事。

不把模型猜测的情绪、关系或人格写入记忆。

## 四、必须跑通的业务流程

### 流程 A：与展示娃娃聊天

1. 用户打开 /d/{dollId}。
2. 服务端建立或恢复匿名会话。
3. 获取娃娃公开资料。
4. 读取当前会话与该娃娃对应的历史消息和记忆。
5. 用户发消息，后端调用真实对话模型并流式返回。
6. 保存消息、回复状态和明确的记忆。
7. 用户关闭后重新访问，同一会话可继续对话。

### 流程 B：创造个人娃娃

1. 用户上传或拍摄照片。
2. 提交 userNickname、personaId；可以提交 accessoryIds 等明确选项。
3. 创建 Card 与 CardVersion，返回稳定任务 ID。
4. 后端异步生成；浏览器按 ID 查询状态。
5. 成功后保存结果资源；用户可以在次数内重新生成，或明确选择模板兜底。
6. 用户选择成功 versionId，并提交娃娃名称。
7. 后端创建 personal Doll，关联选定版本，并写入真实创建信息。
8. 返回 dollId、dollUrl、cardUrl。
9. 打开 dollUrl，读取本次创建的形象、人格和记忆。
10. 用户再次打开仍能找到同一个角色。

### 流程 C：提交模拟出图

1. 选择当前会话拥有的一个成功 CardVersion。
2. 提交模拟出图请求。
3. 后端创建 OutputJob，锁定选定版本。
4. Mock 执行器推进 queued → running → succeeded，或模拟失败。
5. 可按 jobId 查询结果。
6. 返回 mode=mock、physicalExecuted=false，不将其计为实体出图。

### 流程 D：下一轮演示

1. 工作人员执行受保护的重置操作，指定当前演示会话。
2. 清理该会话的演示消息、记忆、创作和任务数据，失效该会话。
3. 预置娃娃、人格配置、其他会话和系统配置保持原状。
4. 新体验使用新的匿名会话。

重置时若存在 running 任务，先拒绝重置并返回冲突；不要删除仍被执行器使用的数据。

## 五、对话与记忆的实现要求

### 5.1 每轮对话输入

按以下来源构造上下文：

1. 当前娃娃的人格与名称。
2. 当前会话与该娃娃的已保存记忆。
3. 最近 20 条已完成的历史消息。
4. 当前用户消息。

上下文上限做成配置项。超过供应商可用额度时，从最旧的历史消息开始裁剪，保留人格、当前消息和明确记忆。

### 5.2 消息写入与重试

- 客户端为每次逻辑发送生成 clientMessageId。
- 服务端先持久化用户消息，再调用模型。
- 同一 sessionId + dollId + clientMessageId 不重复插入用户消息。
- 同一条请求正在运行时，重复发送返回冲突。
- 已成功的重复请求返回已保存回复，不再次调用模型。
- 失败后的主动重试复用同一个 clientMessageId，创建新的回复尝试，不重复用户消息。
- 失败或中断的部分回复可以保留，但标记为 failed/incomplete，后续上下文不把它当作完整回复。
- 正在生成的请求和已经成功的请求分别记录状态。

### 5.3 记忆写入

本版采用明确写入，避免另行搭建自动抽取系统：

- 创建表单的明确选择由后端直接写入。
- 用户发消息时可携带 rememberText，表示这段内容需要被记住。
- 后端保存 rememberText，不依赖第二次模型推理。
- 如果聊天中的“记住……”采用自然语言识别，应在实现说明中记录规则；不能把任意聊天内容都自动永久保存。
- 支持查询和删除指定 memoryId。
- Memory 必须按 sessionId + dollId 读取。

删除记忆后，后续请求不再注入该 Memory。若同一事实仍在近期聊天中，模型仍可能从聊天读到；需要彻底重置时，应同时清理当前会话历史。实现说明应准确区分两者。

## 六、照片、生成与异步任务

### 6.1 照片输入

- 支持 JPEG、PNG、WebP。
- 上传前压缩，后端同时校验大小，最大 2 MB。
- 校验实际文件内容能被解码，不能只信任文件扩展名。
- 处理拍摄方向信息，避免生成输入倒置。
- 不支持的格式返回 UNSUPPORTED_IMAGE；实现者可补充转换，但不改变接口。
- 原始照片只通过授权接口读取，不放到公开娃娃资料中。
- 在 HTTPS 地址验证摄像头能力。
- 若使用云端生图，处理说明应与真实数据流一致。

### 6.2 生成输出

真实 ImageProvider 返回：

- 生成结果资源；
- provider；
- providerRequestId（供应商提供时记录）；
- 实际耗时；
- 可选的名称建议和关键词。

生成成功后，将结果保存到应用控制的持久存储，保存可再次读取的 resultUrl。供应商临时 URL 只作为下载来源。

resultKind 固定取值：

| 值 | 含义 |
| --- | --- |
| generated | 实际模型生成 |
| template | 用户明确选择的预设兜底 |
| mock | 开发或测试模拟结果 |

### 6.3 生成状态与超时

状态：

queued → running → succeeded / failed  
queued → cancelled

具体规则：

- 只允许取消 queued 任务。
- 对 running 任务的取消请求返回 409 TASK_ALREADY_RUNNING；刷新或离开不会重新生成。
- ImageProvider 硬超时默认 60 秒，可配置。
- 原需求“40 秒看到形象”作为性能目标单独记录，不能与硬超时混为一谈。
- 不无限自动重试付费调用。
- 超时、失败、重生成均保留具体记录。
- 迟到的结果不得修改已结束任务或替换已经绑定的版本。
- 若前一个版本失败，用户可以在上限内重生成，也可以明确选择模板版本。
- 模板完成率与真实生成成功率分别统计。

### 6.4 重启恢复

- succeeded、failed、cancelled 保持原状。
- queued 任务可以由执行器恢复处理。
- 无法确认远端结果的 running 任务转为 failed，errorCode=WORKER_RESTARTED。
- 不在重启后自动重复尚不确定是否已付费的模型请求。
- 用户通过原任务 ID 查询确定结果，再决定是否重试。

## 七、Provider 与配置

适配层放在后端，浏览器只访问项目业务 API。

### ChatProvider

输入：人格、历史消息、记忆、当前消息。  
输出：文本增量、结束信息、供应商请求 ID 或错误。

提供 mock 和一种真实 cloud 实现。

### ImageProvider

输入：照片资源、personaId、配饰选项和生成约束。  
输出：结果资源、供应商信息或错误。

提供 mock 和一种真实 cloud 实现。为后续 rdk 实现保留相同契约；本版无需部署 RDK 模型。

### OutputProvider

输入：固定 cardVersionId、资源地址、资源类型、纸张参数。  
输出：执行器任务引用与任务状态。

本版只实现 mock。后续增加 arm 或 printer 实现。

### 配置要求

至少提供以下环境变量示例，具体命名可按项目习惯调整：

| 配置 | 用途 |
| --- | --- |
| APP_BASE_URL | 生成稳定链接 |
| DATABASE_URL | 数据持久化 |
| STORAGE_PATH 或存储服务配置 | 保存照片和生成结果 |
| SESSION_SECRET | 匿名会话签名或会话安全配置 |
| SESSION_TTL_DAYS | 会话有效期，默认 30 |
| CHAT_PROVIDER | mock / cloud |
| CHAT_API_BASE、CHAT_API_KEY、CHAT_MODEL | 真实对话接入 |
| IMAGE_PROVIDER | mock / cloud |
| IMAGE_API_BASE、IMAGE_API_KEY、IMAGE_MODEL | 真实生图接入 |
| IMAGE_TIMEOUT_MS | 默认 60000 |
| CHAT_FIRST_TOKEN_TIMEOUT_MS | 默认 10000 |
| MAX_REGENERATIONS | 默认 2 |
| OUTPUT_PROVIDER | 本版固定 mock |
| DEMO_ADMIN_TOKEN | 演示管理操作授权 |
| PHOTO_TTL_HOURS | 原始照片清理期限，默认 24 小时 |

Provider 开关分别配置。任务创建时保存所用 provider，执行中不随全局配置变化而改变。

真实模式缺少密钥时返回 PROVIDER_NOT_CONFIGURED；不得静默回退为 mock。缺少真实接口条件时，仍应完成可运行的 mock 版本、适配接口和说明，并明确标记哪些真实验收尚未完成。

原始照片到期清理后，已保存的生成结果仍保留；再次请求重生成返回 PHOTO_EXPIRED，用户需新建创作并重新提交照片。

## 八、数据模型

下表是逻辑模型，可按 ORM 或数据库实现细化索引、时间戳和约束。

| 对象 | 关键字段 |
| --- | --- |
| Session | id、isDemo、createdAt、expiresAt |
| Persona | id、name、mbti、prompt、openingLine |
| Doll | id、kind、ownerSessionId、personaId、name、avatarUrl、cardId、cardVersionId |
| Card | id、ownerSessionId、photoRef、userNickname、personaId、accessoryIds、activeVersionId、boundDollId、generationAttempts |
| CardVersion | id、cardId、versionNumber、status、provider、providerRequestId、resultKind、resultUrl、errorCode、startedAt、finishedAt |
| Message | id、sessionId、dollId、clientMessageId、replyAttempt、role、content、status、createdAt |
| Memory | id、sessionId、dollId、type、value、source、createdAt |
| OutputJob | id、ownerSessionId、cardId、cardVersionId、status、mode、physicalExecuted、idempotencyKey、errorCode、createdAt |

必要约束：

- CardVersion 的 cardId + versionNumber 唯一。
- 每个 Card 最多绑定一个个人 Doll。
- demo Doll 不接受用户卡片绑定。
- Message 的用户消息去重键为 sessionId + dollId + clientMessageId；回复尝试单独编号。
- Memory 按 sessionId + dollId 查询。
- 输出任务固定引用成功版本，不在执行时读取“最新版本”。
- 同一 Card 创建新版本时，计数检查和写入放在同一事务内。
- 使用本地数据库和文件存储时，部署必须提供持久磁盘。

## 十、业务 API 契约

所有 JSON 成功响应使用 data 字段；错误格式统一为：

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "可理解的错误说明",
    "requestId": "req_xxx"
  }
}
```

### 通用身份与幂等规则

- session：匿名会话可用。
- owner：服务端识别为资源拥有者。
- admin：通过独立管理授权。
- 未拥有的私有资源统一返回 404。
- 创建、重生成、绑定和出图接受 Idempotency-Key。
- 同一会话、同一操作、同一 Key、相同输入返回原资源。
- 同 Key 不同输入返回 409 IDEMPOTENCY_CONFLICT。
- 刷新通过查询恢复，不重新提交创建请求。
- 客户端用新的 Key 发起真正的新尝试。

### 接口列表

| 方法与路径 | 权限 | 输入 | 输出与关键行为 |
| --- | --- | --- | --- |
| POST /api/session | 无 | 无 | 200；建立或恢复 Cookie，返回 sessionId、expiresAt |
| GET /api/personas | session | 无 | 200；可选人格公开字段，不返回完整内部 Prompt |
| GET /api/dolls/{id} | session | 路径 id | 200；id、kind、name、persona、avatarUrl、dollUrl |
| GET /api/dolls/{id}/messages | session | 可选 cursor、limit | 200；仅当前会话的消息 |
| POST /api/dolls/{id}/chat | session | text、clientMessageId、可选 rememberText | SSE；按下节事件契约返回 |
| GET /api/dolls/{id}/memory | session | 无 | 200；仅当前会话与该娃娃的记忆 |
| POST /api/dolls/{id}/memory | session | type、value | 201；保存明确记忆，返回 memoryId |
| DELETE /api/dolls/{id}/memory/{memoryId} | owner | 路径参数 | 204；删除对应记忆 |
| POST /api/cards | session | multipart：photo、userNickname、personaId、可选 accessoryIds | 202；cardId、versionId、status |
| GET /api/cards/{id} | owner | 路径 id | 200；作品、各版本概要、activeVersionId、剩余生成次数、boundDollId |
| GET /api/card-versions/{id} | owner | 路径 id | 200；status、provider、resultKind、resultUrl、errorCode、耗时 |
| POST /api/cards/{id}/redraw | owner | 幂等键 | 202；新 versionId；超限或 Card 已绑定返回 409 |
| POST /api/card-versions/{id}/cancel | owner | 幂等键 | 200；仅 queued 可取消；running 返回 409 |
| POST /api/cards/{id}/fallback | owner | templateId、幂等键 | 201；新或已有 template 版本；有运行中任务时返回 409 |
| POST /api/cards/{id}/bind | owner | versionId、dollName、幂等键 | 201 首次创建；200 重复请求；返回 dollId、dollUrl、cardUrl |
| POST /api/plot/jobs | owner | cardVersionId、paperSize、幂等键 | 202；jobId、status、mode=mock |
| GET /api/plot/jobs/{id} | owner | 路径 id | 200；status、cardVersionId、mode、physicalExecuted、errorCode |
| GET /api/health | 无 | 无 | 200；服务存活状态，不返回密钥或私人数据 |
| GET /api/demo/status | admin | 无 | 200；provider 配置状态、任务数量、近期错误 |
| POST /api/demo/reset | admin | sessionId | 200；只重置指定的 isDemo 会话；有运行中任务返回 409 |

绑定要求：只有属于当前会话、status=succeeded 的版本可以绑定。versionId 必须属于该 Card。对已绑定 Card 使用其他 versionId 返回 CARD_LOCKED；相同绑定请求返回原 Doll。

输出任务要求：只能引用拥有者的 succeeded 版本，且 resultUrl 可访问。Mock 输出允许输入 PNG、JPEG、WebP；真实机械臂所需 SVG 或路径转换交给后续 OutputProvider 适配。

### 对话 SSE 事件

使用 POST 请求并读取响应流，事件如下：

```text
event: meta
data: {"requestId":"req_xxx","clientMessageId":"msg_xxx","provider":"cloud"}

event: delta
data: {"text":"小林，"}

event: delta
data: {"text":"我是栗子。"}

event: done
data: {"assistantMessageId":"reply_xxx","status":"completed"}

event: error
data: {"code":"CHAT_TIMEOUT","message":"对话请求超时","requestId":"req_xxx"}
```

- 每次流只以 done 或 error 之一结束。
- 流开始前的参数、身份或配置错误通过 HTTP JSON 错误返回。
- 流开始后的错误通过 error 事件返回，并保存失败状态。
- 首 token 目标 3 秒；首次响应硬超时默认 10 秒。两者分别记录。

### 主要错误码

INVALID_INPUT、UNSUPPORTED_IMAGE、IMAGE_TOO_LARGE、PHOTO_EXPIRED、NOT_FOUND、PROVIDER_NOT_CONFIGURED、PROVIDER_ERROR、GENERATION_TIMEOUT、GENERATION_LIMIT_REACHED、TASK_ALREADY_RUNNING、CARD_LOCKED、INVALID_CARD_VERSION、IDEMPOTENCY_CONFLICT、CHAT_TIMEOUT、WORKER_RESTARTED。

## 十二、验收用例

以下是功能验收，不是开发排期。

1. **预置娃娃**：通过固定链接打开，读取正确名称、人格和形象。
2. **真实聊天**：与真实模型连续交流，能利用当前角色设定。
3. **历史恢复**：刷新或关闭再打开，当前会话消息仍可读取。
4. **明确记忆**：保存昵称和一条事实，重新访问后可以正确使用。
5. **会话隔离**：两个独立浏览器访问同一 demo Doll，互相读不到私人历史。
6. **真实生图**：使用一张照片调用真实服务，结果成功持久化。
7. **版本保留**：重生成保留旧版本，失败也计次数，网络重试不新增次数。
8. **绑定闭环**：绑定选定版本后，dollUrl 展示同一角色资料，并能使用创建信息回应。
9. **保护预置角色**：用户创作不会覆盖 demo Doll。
10. **绑定幂等**：重复绑定相同 Card 与版本只返回一个 Doll。
11. **模拟出图**：任务能提交、查询、完成，并保留 mock 来源与 physicalExecuted=false。
12. **防重复**：重复请求不新增生成版本或重复出图任务。
13. **取消与迟到结果**：queued 可取消，running 返回明确冲突，已结束任务不被迟到结果改写。
14. **重启恢复**：成功结果保留，queued 可恢复，未知 running 明确失败。
15. **错误来源清楚**：密钥缺失、供应商失败和模板兜底可以区分。
16. **连续演示**：重置本轮后可开始新会话，其他会话和预置配置不受影响。
17. **实际性能记录**：分别记录真实对话首 token、生图端到端耗时；mock 不计入真实模型成功率。
18. **真实能力证据**：至少保留一次真实对话和一次真实生图的运行记录；条件不足时标为未验收。

核心演示验收：

“上传照片 → 选择人格 → 生成形象 → 起名字并绑定 → 再次打开娃娃链接 → 角色准确提到创建时的称呼与选择 → 提交模拟出图任务”。
